## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | Dungeon & Dine: 飢餓のトレジャーハンター（仮） |
| リポジトリ名 | `dungeon-and-dine` |
| ジャンル | ローグライクRPG（ターン制・8方向グリッド） |
| 言語・フレームワーク | Python 3.11 以上 / Pyxel 2.x（`pyxel>=2.0,<3`） |
| プラットフォーム | OS非依存（Windows / macOS / Linux で同一の挙動） |

| プレイ時間の目安 | 1回の挑戦（B1F〜B20F）で 60〜90分【仮】 |

## 2. 開発・技術スタック要件

### 2.1 全般
- Pyxel のゲームループ（`update` / `draw`）で構築する。
- クラスベースのオブジェクト指向で実装し、画面遷移はシーン（State）で管理する。エンティティは `dataclass` を基本とする。
- 型ヒントを必須とし、PEP 8 に準拠する（リンターは ruff を推奨）。
- 役割ごとにモジュールを分割する（単一ファイルにしない）。
- **ロジックと描画を分離する。** `world/` `entities/` `systems/` 配下では `pyxel` を import しない。これにより、ゲームロジックを pytest で単体テストできるようにする。

### 2.2 クロスプラットフォーム
- ファイルパスはすべて `pathlib.Path` で扱い、パス区切り文字をハードコードしない。
- リソースのパスは `Path(__file__).resolve().parent` を起点に組み立てる（カレントディレクトリに依存しない）。
- セーブデータの保存先は `pyxel.user_data_dir("dungeon-and-dine", "dungeon-and-dine")` を使う（OSごとに適切なユーザーデータフォルダが返る）。
- ファイルの読み書きは常に `encoding="utf-8"` を指定する。

### 2.3 画面・描画（探索画面）
普段の探索画面は、**小さなタイルで描くシンプルなドット絵**とする。真上から見下ろした、ローグ系の見た目にする。

> **重要: ASCII文字による表示は禁止**
> - 主人公、モンスター、アイテム、宝箱、罠、床、壁、階段などは、すべてドット絵（画像素材）で描画する。
> - 本家ローグのように `@` `#` `.` などの文字でマップやキャラクターを表す実装は、仮素材も含めて行わない。
> - 文字（フォント）を使うのは、ステータス、ログ、メニューなどのテキスト表示だけとする。

| 項目 | 値 |
|---|---|
| ウィンドウサイズ | 640 × 480 px（4:3） |
| 表示倍率 | `display_scale=1`（640×480。起動引数で変更可。2 で 1280×960） |
| FPS | 30 |
| タイル・キャラクターのサイズ | 16 × 16 px（ボスのみ 32 × 32 px）。素材も同じ大きさで描き、拡大せずに表示する |
| 上部ステータスバー | 640 × 40 px（2行） |
| マップ表示領域 | 640 × 360 px（40 × 22 タイル）。プレイヤーを中心にカメラをスクロールする |
| 下部パネル | 640 × 80 px（コマンドバー1段＋ログ2行） |
| 1マップのサイズ | 64 × 48 タイル【仮】 |

**画面レイアウト**
```
┌────────────────────────────────────────────────┐
│B4F 苔むす洞窟   Lv8  EXP 2950/4000   1340G      │ ← ステータスバー
│HP ■■■■□ 48/60  MP ■■■□□ 19/25  満腹 ■■■■□ 72 │
├────────────────────────────────────────────────┤
│  ########          ##########                  │
│  #......#          #........#                  │
│  #..@...+##########+...r....#   （16×16のドット絵│
│  #...$..#          #..^..▣..#     タイルで描画）│
│  ########          ##########                  │
├────────────────────────────────────────────────┤
│[攻撃][道具][スキル][料理][装備][地図]          │
│> 巨大ネズミが現れた！                          │
│> ネズミに5のダメージ                          │
└────────────────────────────────────────────────┘
```
※ 上の記号は、本書で配置を説明するためだけのもの。**実際の画面では記号や文字を使わず、それぞれのドット絵を描画する**（@=レオ、r=モンスター、$=アイテム、^=落とし穴、▣=宝箱、#=壁、.=床、+=通路の入口）。

- **ステータスバー:**
  - 1行目: 階層、エリア名（5.6）、Lv、EXP（現在値/次のレベルまで）、所持金
  - 2行目: HP・MP・満腹度のゲージと数値
- **下部パネル:**
  - 1段目: コマンドバー（3.1）
  - 2〜3段目: 最新2件のログ
- **ミニマップ:** 常時は表示しない。地図コマンド（M）で全体マップを表示する。

### 2.3.1 ドット絵の要件
すべて 16×16 px（ボスのみ 32×32 px）、Pyxel の16色、透過色は 0（黒）とする。見分けやすさを優先し、シルエットと色でキャラクターを区別する。

| 分類 | 描くもの | アニメーション |
|---|---|---|
| 主人公 | 見た目5種（戦士・格闘家・魔法使い・僧侶・商人）×上下左右の4方向。斜め移動のときは左右の絵を使う | 各方向2フレームの待機・歩行 |
| モンスター | 8.2 の通常20種（1種につき1〜2フレーム）。ボス5種は 32×32 | 2フレームの待機 |
| 地形 | 床、壁、通路、下り階段、焚き火、安全地帯の床 | 焚き火は3フレーム |
| エリアの違い | 床と壁は、エリア（5.6）ごとに色違いを用意する | - |
| オブジェクト | 宝箱（閉／開）、ミミック（擬態時は宝箱と同じ絵） | - |
| 罠（発見後のみ表示） | 落とし穴、毒矢、睡眠ガス、ワープ、空腹、錆び、警報 | - |
| アイテム | 武器5種、盾、兜、鎧、靴、食材、料理、謎の物体、草、巻物、ルーペ、聖水、携帯コンロ、矢、先人のメモ、お金 | - |
| エフェクト | 攻撃の閃光、矢、炎のブレス、ダメージ数字 | 2〜3フレーム |

- **既知タイル（視界外）の表示:** 同じドット絵を、`pyxel.pal()` で暗い色に置き換えて描く。
- **モンスターの色違い:** 使い回しは可とするが、同じ階に出る敵どうしは見分けられる色にする。
- **縁取り（必須）:** 敵・宝箱・床に落ちているものは、1px の黒い縁を付けて描く。
  16色しかないため、床と同じ色の敵や品物が出るのを避けられない（色を個別に変えても、
  エリアや敵を追加するたびに再発する）。描画側で輪郭を分けて、どのエリアでも見分けられるようにする。
  実装は `ui/sprites.py` の `SpriteSheet.draw(outline=...)`。全色を縁の色に差し替えて
  上下左右へ1pxずらして描き、その上に本来の絵を重ねる（透明の判定は差し替える前の色で行われる）。
- **素材の置き場所:** `assets/resources.pyxres` のイメージバンク0（16×16 の素材シート。ボスだけ 32×32）。1枚（256×256）に入りきらない分は次のイメージバンクへ送る。どの素材がどの位置にあるかは `data/sprites.json` で管理する（例: `"rat": {"u": 0, "v": 16, "frames": 2}`。バンク0以外にあるものは `"bank": 1` を持つ）。
- **仮素材:**
  - フェーズ1〜4では、簡易なドット絵の仮素材でよい。
    - 例: 壁はレンガ模様の四角、床は点を散らした四角、主人公は緑の人型、モンスターは種類ごとに色を変えた丸型。
    - 仮素材でも、文字を載せて種類を区別してはならない。
  - 仮素材は、`tools/make_placeholder_sprites.py` などのスクリプトでイメージバンクに描き込んで作ってよい。
  - `sprites.json` を差し替えるだけで本素材に切り替わる作りにする。
- 16色パレット以外の色は使わない（料理カットインのときだけ例外。2.4 参照）。

### 2.4 料理カットイン画面
調理を行うときだけ、参考画像 `cooking_cutin_concept.jpg` のような描き込んだ1枚絵の画面に切り替える。

- **画面構成:**
  - 背景: 焚き火を囲む洞窟の1枚絵（素材は 320 × 140 px。画面へは2倍の 640 × 280 px に拡大し、上下の余白は暗い色で埋める）
  - アニメーション部品（背景の上に重ねて描く）:
    - 炎: 3〜4フレーム
    - 湯気: パーティクルで表現
    - 串の肉: 焼き色が2段階で変化
    - レオの手元: 2フレーム
    - 携帯コンロで調理するときは、焚き火の代わりにコンロの部品を描く
  - 下部 640 × 80 px: 食材選択と結果のテキストウィンドウ
- **素材:**
  - 背景は `assets/cutins/cooking_<エリアID>.png` に置く。
  - 起動時に、`pyxel.Image` として読み込む（幅が256pxを超えるため、イメージバンクには入れない）。
  - アニメーション部品は、仮素材（2.3.1）が使っていないイメージバンクに置く。
  - 最低限、背景は「苔むす洞窟」の1枚でよい。そのエリアの背景がなければ、この1枚を使う。
- **色:**
  - カットインの間だけ、`pyxel.colors` を料理画面用の16色パレット（`data/palettes.json`）に入れ替える。
  - 画面を閉じるときに、元のパレットへ戻す。
  - 16色の範囲で、ディザリング（ドットの点描）により深い緑や暖色のグラデーションを表現する。
  - 16色を超えるパレット拡張は、使用する Pyxel のバージョンで動作を確認できた場合だけ使ってよい。
- **注意:** 参考画像そのものは、解像度・色数・権利関係の面で素材として使わない。320×140、16色で描き直す。

### 2.5 日本語フォント（必須）
- Pyxel の組み込みフォントは英数字しか表示できないため、日本語の表示には BDF フォントを使う。
- 採用フォントは **美咲ゴシック第2（8×8 px、BDF版）**。`assets/fonts/` に配置し、ライセンス文書も同じ場所に同梱する（ライセンス条件は配布元で確認すること）。
- 読み込み方: `font = pyxel.Font(path)` → `pyxel.text(x, y, s, col, font)`。
- 8px のフォントを2倍に拡大して描き、行の高さは 20 px とする（全角文字で1行あたり最大40文字。ログがはみ出す場合は折り返す）。
- フォントは `ui/font.py` で一元管理し、すべての文字描画はそこに用意したヘルパー関数を経由する。

### 2.6 乱数とシード
- グローバルな `random` モジュールの関数は使わない。`random.Random` のインスタンスを依存性として渡す。
- 挑戦ごとに「ランシード」を決める。各階層のシードは `hash((run_seed, floor))` から導出する。
- 起動引数 `--seed <int>` で、同じダンジョンを再現できるようにする（テスト・デバッグ用）。
- 現在のシードはデバッグ表示（F1キー）で確認できるようにする。

### 2.7 データの外部化
敵・アイテム・レシピ・バランス値は、次の JSON ファイルに定義する。

- `enemies.json` / `weapons.json` / `armors.json` / `items.json`
- `ingredients.json` / `recipes.json` / `traps.json`
- `status_effects.json` / `skills.json` / `sprites.json` / `palettes.json` / `floors.json`（エリア名・タイルの色を含む） / `balance.json`

起動時に `data_loader.py` で読み込み、スキーマを検証する（必須キーが欠けていれば起動時にエラーにする）。

## 3. 操作（入力）

### 3.1 コマンドバー
探索画面の下部パネルに、7つのコマンドを常に表示する。

| コマンド | 内容 |
|---|---|
| 攻撃 | 向いている方向へ通常攻撃する |
| 道具 | インベントリを開く |
| スキル | スキル一覧を開く（6.8） |
| 料理 | 調理画面を開く。焚き火の隣か、携帯コンロを持っているときだけ選べる。選べないときは灰色で表示する |
| 話す | 行商人との対話画面を開く（12.4）。行商人の隣にいるときだけ選べる。選べないときは灰色で表示する |
| 装備 | 装備画面を開く |
| 地図 | 階層全体のマップを画面いっぱいに表示する（既知タイルのみ） |

- 選び方:
  - Tab キー（ゲームパッドは X ボタン）でコマンドバーにフォーカスを移し、左右キーで選んで決定する。
  - 下の表のショートカットキーでも直接実行できる。
  - マウスでクリックしても選べる。
- コマンドバーにフォーカスがある間、方向キーでキャラクターは動かない。

### 3.2 キー割り当て

| 操作 | キーボード | ゲームパッド |
|---|---|---|
| 移動（上下左右） | 矢印キー / WASD | 十字キー |
| 斜め移動 | テンキー 7・9・1・3、または Shift を押しながら2方向同時押し | LB を押しながら十字キー |
| 方向転換のみ | Ctrl を押しながら方向キー | RB を押しながら十字キー |
| 攻撃・決定・調べる | Space / Enter | A |
| キャンセル・閉じる | Esc / X | B |
| コマンドバーへフォーカス | Tab | X |
| 道具（インベントリ） | I | - |
| スキル | K | - |
| 料理 | C | - |
| 装備 | E | - |
| 地図 | M | - |
| レシピ手帳 | R | Y |
| 足踏み（1ターン待機・周囲の罠を探す） | . / テンキー 5 | LB＋A |
| 階段を降りる | 階段の上で Enter | 階段の上で A |
| ログ履歴 | L | Select |
| デバッグ表示 | F1（開発ビルドのみ） | - |

- キー割り当ては `config.py` にまとめて定義する。
- 押しっぱなしの場合、0.15秒ごとに連続移動する【仮】。ただし、敵が視界に入った時点で連続移動を止める。

## 4. シーン（画面遷移）

```
TITLE ──(はじめる/つづきから)──> BASE_CAMP ──(出発)──> DUNGEON
  ^                                 ^   ^                    │
  │                                 │   └──(帰還の巻物で生還)──┤
  │                                 └──────── GAME_OVER <─(HP0)┤
  └────────────── ENDING <──────────────(ボス撃破)───────────────┘
```

DUNGEON シーンは、内部で次のサブモードを持つ。
- `EXPLORE`: 通常の探索
- `COMMAND_BAR`: コマンドバーの選択中
- `INVENTORY`: インベントリ画面
- `EQUIPMENT`: 装備画面
- `SKILL_MENU`: スキル一覧
- `FULL_MAP`: 全体マップ
- `ITEM_MENU`: アイテムの使う／装備する／捨てる／投げる
- `COOKING_CUTIN`: 料理カットイン画面（食材選択 → 調理演出 → 結果表示。9.3）
- `NOTEBOOK`: レシピ手帳
- `CONFIRM`: 確認ダイアログ
- `LOG_HISTORY`: ログ履歴
- `TARGETING`: 弓の方向指定など

サブモードを開いている間はターンが進まない。

## 5. コアシステム

### 5.1 ターン制・行動順
- プレイヤーが1アクション（移動、攻撃、アイテム使用、装備変更、調理、足踏み）を行うと1ターン経過し、その後に全モンスターが行動する。
- メニューを開く・閉じる、手帳やログを見る、といった操作ではターンを消費しない。
- **速度システム:** 各エンティティは「速度」を持つ（通常=100、倍速=200、鈍足=50）。毎ターン速度ぶんのエネルギーを加算し、100に達するごとに1回行動する。
- 行動順は、プレイヤー → モンスター（生成順）とする。

### 5.2 グリッド移動
- 移動は8方向。斜め移動では、移動方向に隣接する2マスのどちらかが壁なら通れない（角抜け禁止）。
- 移動先に敵がいる場合、その方向への攻撃になる。
- アイテムの上に移動すると自動で拾う。インベントリが満杯のときは「持ちきれない」とログに表示する。

### 5.3 マップ生成
- アルゴリズムは **BSP法**。部屋数は4〜9【仮】で、部屋同士を通路でつなぐ（すべての部屋が到達可能であることを保証する）。
- タイルの種類: 壁、床、通路、下り階段、焚き火、宝箱、罠（非表示／発見済み）。
- 下り階段は各階に1つ。プレイヤーの初期位置とは別の部屋に置く。

**配置ルール【仮】**

| 対象 | 数・条件 |
|---|---|
| 初期モンスター | 4〜8体（プレイヤーのいる部屋には置かない） |
| 追加モンスター | 50ターンごとに、視界外に1体出現 |
| 床アイテム | 8〜12個 |
| 宝箱 | 1〜3個（20%は罠付き） |
| 罠 | 3〜6個 |
| 焚き火 | 各階30%の確率で1つ。B5F / B10F / B15F / B19F には必ず置く |

- B20F はランダム生成せず、固定レイアウトのボス階とする（8.3 参照）。手前の部屋に焚き火を置き、階段は置かない。

### 5.4 視界（FOG）
各タイルは「未踏」「既知」「視界内」の3状態を持つ。

| 状態 | 表示 |
|---|---|
| 未踏 | 黒 |
| 既知 | 暗い色で表示する。敵とアイテムは表示しない |
| 視界内 | 通常の表示 |

- **部屋の中:** 部屋全体（壁を含む）が視界内になる。
- **通路:** 隣接1マスに加え、進行方向に直線で最大4マス（壁で遮られる）。
- 兜の「視界拡張」は、通路での隣接範囲を +1 する。
- 状態異常「盲目」の間は、隣接1マスしか見えない。

### 5.5 階層の移動
- 下り階段の上で「降りる」を選ぶと次の階へ進む。ステータスと所持品は引き継ぐ。
- 階を移るとき、中断用データを自動セーブする（13章）。
- 上り階段は存在しない（戻れない）。
- **最下層はない。** 迷宮はどこまでも下へ続く。
- 迷宮から出る方法は「死ぬ」か「帰還の巻物を使う」かの2つだけ（6.6 / 12.3）。
- 20階ごと（B20F、B40F、……）がボス階。ボス階にも下り階段はあるが、**そのボスを倒すまで降りられない**（8.3）。

### 5.6 エリア
20階を1周として、5つのエリアに分ける。エリアごとに名前、タイルの色、出現する敵の傾向を変える（`floors.json` で定義する）。

| 階層 | エリア名【仮】 | 雰囲気 |
|---|---|---|
| B1F〜B5F | 苔むす洞窟 | 緑の苔、光るキノコ、水たまり |
| B6F〜B10F | 骸骨の地下墓地 | 灰色の石棺、骨 |
| B11F〜B15F | 灼熱の坑道 | 赤茶の岩、溶岩の筋 |
| B16F〜B19F | 影の深淵 | 紺と紫の暗い石 |
| B20F | 奈落の底 | ボス部屋 |

- **B21F から下は、この20階分をくり返す。** エリア名には周回数を付けて「苔むす洞窟（深層2）」のように表示する。
- 2周目から下は、敵を規則で強くした「上位種」が出る。1周ごとに HP +35%、攻撃力 +25%、防御 +20%、経験値 +60%【仮】とし、名前に「・深種」「・深深種」と付ける（倍率は `balance.json` の `spawn` で定義する）。
- 階に入ったとき、画面中央に「B4F 苔むす洞窟」のように2秒ほど表示する。以降は右上に常に表示する。

## 6. ステータスとリソース

### 6.1 プレイヤーのステータス【仮】

| ステータス | 初期値 | 説明 |
|---|---|---|
| Lv | 1 | 上限は30 |
| HP / 最大HP | 30 / 30 | |
| MP / 最大MP | 10 / 10 | スキルに使う（6.7） |
| 力（ATK） | 5 | 武器の攻撃力を加算する |
| 防御（DEF） | 2 | 防具の防御力を加算する |
| 命中 | 90 | % |
| 回避 | 5 | % |
| 満腹度 | 100 / 100 | |
| 経験値 | 0 | |
| 所持金 | 0 G | |

- 主人公の名前は、ゲームを始めるときに入力する（10文字まで【仮】）。五十音表（ひらがな・カタカナ・英数）から選ぶ方式とし、濁点・半濁点も付けられる。キーボードからの半角英数の直接入力も受け付ける。未入力のときは「レオ」を使う。入力した名前は `meta.json` に保存し、次回以降の既定値にする。ログでは「〇〇は〜」と、入力した名前で表示する。
- 名前を入力したあとに、主人公の見た目を「戦士・格闘家・魔法使い・僧侶・商人」の5種から選ぶ。**見た目だけの違いで、ステータスやスキルは変わらない。** 選んだ見た目は `meta.json` に保存して次回以降の既定値にし、挑戦中の見た目は `run.json` にも保存する。選ぶ前のセーブデータでは戦士にする。

### 6.2 レベルアップ【仮】
- 次のレベルまでに必要な経験値は `floor(10 × Lv^1.5)`。
- レベルが上がるごとに、最大HP +5、最大MP +2、力 +1、防御 +1（奇数レベルのみ）。HP と MP は上昇分だけ回復する。
- 特定のレベルに達すると、スキルを習得する（6.8）。

### 6.3 満腹度【仮】
- 最大100。10ターンごとに1減る（呪い・装備の効果で倍率が変わる）。
- 満腹度が20以下で「おなかが減ってきた」、0で「飢えている」とログに表示する。
- 満腹度が0の間は、毎ターン HP が1減り、HP の自然回復が止まる。

### 6.4 HP の自然回復【仮】
- 満腹度が1以上のとき、5ターンごとに HP が1回復する（毒状態のときは回復しない）。

### 6.5 ダメージ計算【仮】
```
命中判定:   hit% = clamp(攻撃側の命中 - 防御側の回避, 5, 95)
ダメージ:   dmg = max(1, round(ATK × rand(0.9, 1.1) - DEF × 0.5))
クリティカル: 5%（刀は20%）で dmg × 1.5
盾ブロック:  盾の発動率でダメージを0にする
```
- ATK = 力 + 武器攻撃力 + 修正値 + バフ
- DEF = 防御 + 防具防御力の合計 + 修正値 + バフ

### 6.6 死亡（パーマデス）
- HP が0になると GAME_OVER シーンへ移る。
- 所持品、装備、レベル、所持金をすべて失い、拠点に戻る。
- 引き継がれるものは 12.3「メタプログレッション」を参照。
- ゲームオーバー画面では、これまでの挑戦のランキングを表示する。「到達した階層」と「獲得した所持金」の2種類を、それぞれ上位10件まで並べる（左右キーで切り替える）。

### 6.7 MP【仮】
- 最大MPの初期値は10。スキルを使うと消費する。
- 満腹度が1以上のとき、10ターンごとに MP が1回復する。満腹度が0の間は回復しない。
- 回復手段:
  - 消費アイテム「魔力草」（MP +15）
  - 一部の料理（9.5）
  - 階段を降りたとき、最大MPの20%が回復する

### 6.8 スキル【仮】
- レベルアップで自動的に習得する。習得したスキルはスキル一覧から選んで使う。
- 使うと MP を消費し、1ターン経過する。
- 攻撃スキルは、向いている方向を基準に範囲を決める。
- 攻撃スキルのダメージは、通常攻撃のダメージ（6.5）に表の倍率を掛けて求める。命中判定も通常攻撃と同じ。
- 死亡・生還でレベルが1に戻ると、習得したスキルもリセットされる（再び同じレベルで習得する）。
- スキルは `skills.json` に定義する。

| スキル | 習得Lv | 消費MP | 効果 |
|---|---|---|---|
| 解体術 | 1 | 3 | 前方1マスを攻撃（ダメージ×0.8）。この攻撃で倒すと、食材が必ずドロップする |
| 強撃 | 3 | 4 | 前方1マスを攻撃（ダメージ×1.8） |
| 薙ぎ払い | 6 | 6 | 周囲8マスすべてを攻撃（ダメージ×1.0） |
| 目利き | 9 | 8 | インベントリの未鑑定装備1つについて、呪いの有無だけを判明させる |
| 忍び足 | 12 | 8 | 20ターンの間、`wander` 状態の敵がプレイヤーに気づかない |
| 火起こし | 15 | 12 | 向いている方向の隣の床に焚き火を作る（30ターンで消える。1つの階につき1回まで） |
| 捨て身の一撃 | 20 | 15 | 前方1マスを攻撃（ダメージ×3.0）。自分も最大HPの10%のダメージを受ける |

- 呪いの効果「スキル封じ」（10.6）を受けている間は、スキルを使えない。

### 8.3 ボス（20階ごと）【仮】

20階ごとにボス階を置く。出る順は `floors.json` の `bosses` で定義し、5体を使い切ったら先頭へ戻って、5.6 と同じ規則で強化する。

| 階層 | ボス【仮】 | HP / ATK / DEF / EXP | 到達レベルの想定 | 勝率【仮】 |
|---|---|---|---|---|
| B20F | 奈落の大喰らい | 240 / 33 / 12 / 500 | Lv15 | 70% |
| B40F | 骸骨王 | 320 / 36 / 15 / 900 | Lv19 | 72% |
| B60F | 溶岩の暴君 | 400 / 39 / 20 / 1400 | Lv23 | 70% |
| B80F | 虚無の熾天使 | 460 / 42 / 24 / 2000 | Lv27 | 69% |
| B100F | 迷宮の造り主 | 530 / 43 / 28 / 3000 | Lv30 | 72% |

- **ボスの攻撃力は、プレイヤーの防御力の伸びに連動させる**（防御の約1.55倍）。
  プレイヤーは最大レベル30で頭打ち（HP272 / 攻撃69 / 防御28）になるため、
  ボスの攻撃力だけを伸ばすと、ある階層から先は理論上勝てなくなる。
  手応えは HP と経験値で付け、攻撃力ではインフレさせない。
- 勝率は、到達レベルの想定・終盤装備・HP満タンで1対1を戦わせた実測値（`tools/` の検証スクリプトによる）。

- **ボスは色ではなく形で見分けられるようにする。** 大喰らい（丸い口）、骸骨王（王冠を頂く頭蓋）、
  溶岩の暴君（角張った岩塊）、虚無の熾天使（翼）、迷宮の造り主（菱形の幾何学体）と、
  輪郭の時点で別物と分かる絵にする。色違いだけでは、小さく表示したときに同じ敵に見えてしまう。
  体の色には、ボス階の床の色（1）と床の点の色（2）を使わない（背景に沈むため）。
- ボスを倒すと下り階段が使えるようになり、さらに下へ進める。
- **B100F の「迷宮の造り主」を倒すとエンディング**。それより下へも潜り続けられる。

以下は B20F「奈落の大喰らい」の行動パターン。他のボスも同じ枠組み（咆哮・憤怒・捕食）で、数値と付与する状態異常だけを変える。

「奈落の大喰らい」
- HP 300 / ATK 28 / DEF 12 / 速度 100。1マスの大きさで扱う。
- 行動パターン:
  - 通常は `chase` で追跡し、隣接したら攻撃する。
  - 4ターンごとに「咆哮」を使う。周囲5マス以内にいるプレイヤーを鈍足にする。
  - HP が50%以下になると速度200になる。
  - HP が25%以下になると「捕食」を使う。隣接するプレイヤーの満腹度を20減らし、そのぶん自分の HP を回復する。
- 撃破すると ENDING シーンへ移る。

## 9. モンスター調理・料理システム

### 9.1 食材のドロップ【仮】
- 基本ドロップ率は30%。
- 倒した手段によってドロップが変わる:
  - **ナイフ**で倒すと、ドロップ率が1.5倍になる。
  - **炎属性**（火炎の巻物、炎の印が付いた武器）で倒すと、生の食材が調理済みの「焼き〇〇」になる。焼き〇〇はそのまま食べられ、満腹度を +25 回復する。
- **生肉は腐る。** 取得から500ターンで「腐った肉」に変わる。腐った肉を食べると満腹度 +5 と毒になる。調理済みの食材は腐らない。
- 生の食材をそのまま食べると満腹度 +10 回復するが、30%で毒になる【仮】。

|---|---|---|
| スライムゼリー | ゼリー類 | |
| ネズミ肉 | 肉類 | 腐る |
| コウモリの羽 | 素材類 | |
| 光るキノコ | キノコ類 | 床にも落ちている |
| 骨 | 素材類 | |
| 蛇肉 | 肉類 | 腐る |
| 火トカゲの尻尾 | 肉類 | 腐る |

### 9.3 調理の実行
- **調理手段:**
  - **焚き火:** 焚き火のマスに隣接しているか上に立っているときに調べると使える。回数制限なし。焚き火の周囲8マスは安全地帯で、敵が侵入せず、出現もしない。
  - **携帯コンロ:** 消費アイテム。1個につき3回使える。視界内に敵がいるときは使えない。
- **材料:** インベントリから2〜3個を選ぶ（食材以外のアイテムも入れられる）。
- **所要時間:** 材料の数にかかわらず1ターン消費する。
- **カットインの流れ:** 料理コマンドを選ぶと、探索画面から料理カットイン画面（2.4）に切り替わる。

  | 段階 | 内容 | 時間 |
  |---|---|---|
  | 1. 切り替え | ディザリングのワイプで、探索画面からカットインへ移る | 0.3秒 |
  | 2. 食材選択 | 背景の上に食材選択ウィンドウを表示する（14章「調理画面」）。キャンセルするとターンを消費せずに探索画面へ戻る | 入力待ち |
  | 3. 調理演出 | 肉が焼ける、湯気が立つ、炎が揺れるアニメーション。テキストは「レオは〇〇を焼いている……」 | 約1.5秒 |
  | 4. 結果表示 | 成功: 料理名と効果を表示し、キラキラのエフェクトを出す。失敗: 黒い煙を出し、「謎の物体ができた……」と表示する | 決定キーを押すまで |
  | 5. 復帰 | ワイプで探索画面に戻る。ここで1ターン経過し、結果をログに残す | 0.3秒 |

  - 段階1〜5の間はターンが進まず、敵も動かない。
  - 段階3では入力を受け付けない。
  - 設定で段階3を0.3秒に短縮できるようにし、段階1・5のワイプも省略できるようにする。
- 材料は成否にかかわらず消費する。

### 9.4 レシピ照合ロジック
- 材料の順序は区別しない（多重集合として比較する）。
- レシピの材料は「食材ID」か「タグ」で指定する。照合は次の優先順で行う。
  1. すべて ID で完全一致するレシピ
  2. タグ指定を含むレシピ（ID 指定の数が多いものを優先）
- 一致するレシピがなければ「謎の物体」になる。
- 既知のレシピでも、基本失敗率5%で失敗する（呪いの効果で +30%）。

`recipes.json` の例:
```json
{ "id": "rat_skewer", "name": "ネズミ肉の串焼き",
  "ingredients": [{"id": "rat_meat"}, {"id": "herb"}],
  "effects": [{"type": "satiety", "value": 40}, {"type": "heal", "value": 20}] }
```

### 9.5 レシピ一覧【仮】
| 料理名 | 材料 | 効果 |
|---|---|---|
| ネズミ肉の串焼き | ネズミ肉＋薬草 | 満腹度+40、HP+20 |
| スライムゼリー寄せ | スライムゼリー＋光るキノコ | 満腹度+20、HP+50、MP+10 |

### 9.6 レシピの発見と手帳
- **試行錯誤:** 未知の組み合わせで調理すると結果が判明する。
  - 成功したレシピは手帳に登録する。
  - 失敗した組み合わせも「失敗リスト」に記録し、調理画面で ✕ 印を表示する。
- **先人のメモ:** ダンジョンで拾える消費アイテム。読むと未発見のレシピが1つ手帳に登録される。未発見のレシピがなければ、代わりに 50G を得る。
- **手帳画面:** 発見済みの料理名、材料、効果を一覧で表示する。未発見のレシピは「？？？」と表示し、発見率（例: 4/11）も表示する。
- 手帳のデータはメタデータとして永続保存し、死亡しても消えない。

## 10. 装備・ハクスラシステム

### 10.1 装備スロット
武器×1、盾×1、兜×1、鎧×1、靴×1。装備中のアイテムもインベントリの枠を1つ使う。

### 10.2 武器【仮】
| 武器 | 攻撃力 | 攻撃範囲 | 特性 | 備考 |
|---|---|---|---|---|
| 素手 | 0 | 前方1マス | - | 武器を装備していないとき |
| ナイフ | 2 | 前方1マス | 食材ドロップ率 ×1.5 | |
| 槍 | 4 | 前方2マス（貫通） | 2マス先の敵にも同時に当たる | |
| ムチ | 2 | 前方の扇状3マス（正面＋その左右斜め） | 攻撃範囲に敵がいないとき、正面の直線3マス以内にある最も近いアイテムを足元に引き寄せる | |
| 弓 | 3 | 正面の直線で最大8マス | 矢を1本消費する。最初に当たった敵のみ | 矢がないときは素手扱い |
| 刀 | 6 | 前方1マス | クリティカル率20% | レア（出現率低） |

- 「前方」とはプレイヤーが向いている方向（8方向）を指す。斜め方向の範囲は、正面の方向ベクトルを基準に算出する。

### 10.3 防具【仮】
| 部位 | 防御力 | 固有効果 |
|---|---|---|
| 盾 | 2〜5 | 15%の確率でダメージをブロック |
| 兜 | 1〜3 | 視界拡張、状態異常耐性（両方付くかは種類による） |
| 鎧 | 3〜8 | 最大HP +5〜15 |
| 靴 | 0〜2 | 罠発見率 +20%、満腹度の減少を 0.8 倍に |

### 10.4 修正値と印
- 装備品は修正値（-3〜+5）を持ち、攻撃力または防御力に加算される。名前は「槍+2」のように表示する。
- 20%の確率で「印」が1つ付く【仮】。印の種類は次のとおり。
  - 炎（攻撃が炎属性になる）
  - 会心（クリティカル率 +10%）
  - 頑丈（錆びない）
  - 腹持ち（満腹度の減少 0.8 倍）

### 10.5 入手と未鑑定
- 主な入手手段:
  - 宝箱（通常・罠付き）
  - 床への配置
  - ミミックのドロップ
  - 道具屋での購入（購入品は鑑定済み）
- ダンジョンで拾った装備は未鑑定状態になる。
  - 表示名は「？の槍」のように種類だけを示し、修正値・印・呪いの有無は「???」と表示する。
- **鑑定手段:**
  - 装備する（その時点で全性能が判明する。呪われていれば呪いが発動する）
  - 消費アイテム「鑑定のルーペ」を使う（1個につき1品。呪いの有無も判明する）
  - 拠点の鑑定屋に頼む（有料）
- 判明した情報は、そのアイテム個体にだけ適用する（「同じ種類はすべて判明する」方式は採用しない）。

### 10.6 呪い
- 呪いの有無は、アイテムの生成時に内部フラグとして決める。
  - 呪われる確率は、未鑑定装備の25%を基本とし、B11F 以降は35%【仮】。
  - プレイヤーから見ると「装備した瞬間に一定確率で呪いが発動する」挙動になる。
- **発動時:**
  - 画面効果とSEで呪いを演出する。
  - その部位の装備が外せなくなる。
  - 修正値がマイナスになる。
  - 次のどれか1つのマイナス効果が付く。
    - 命中率半減
    - スキル封じ（スキルを使えない）
    - 満腹度の減少2倍
    - 料理の失敗率 +30%
    - 視界 -1
    - 罠を発見できなくなる
- 呪われていることが判明している装備も、装備はできる（確認ダイアログを表示する）。
- **解呪手段:**
  - ダンジョン内:
    - 「解呪の巻物」: 装備中のすべての呪いを解く
    - 「聖水」: 選んだ1品の呪いを解き、修正値を +1 する
  - 拠点: 解呪屋で1品につき 200G【仮】を払う。生還したときのみ利用できる。

### 11.1 インベントリ
- 容量は初期20枠。拠点の拡張で最大30枠まで増やせる。

- アイテムメニューの項目:
  - 使う／食べる／読む
  - 装備する／外す
  - 投げる（前方の直線5マス、当たるとダメージ2）
  - 捨てる（足元に置く）

## 12. 罠・宝箱・拠点

### 12.1 罠【仮】
| 罠 | 効果 |
|---|---|
| 落とし穴 | ダメージ5を受け、次の階へ落ちる |
| 毒矢 | ダメージ3と毒 |
| 睡眠ガス | 睡眠 |
| ワープ | 同じ階のランダムな位置へ移動 |
| 空腹の罠 | 満腹度 -20 |
| 錆びの罠 | 装備中の武器か防具1つの修正値 -1（「頑丈」の印があれば無効） |
| 警報 | その階のすべての敵がプレイヤーの位置へ向かう |

- 罠は最初は見えない。次のタイミングで発見判定を行い、発見すると表示する。
  - 足踏みしたとき: 周囲8マスを判定（基本発見率10%、靴で +20%）
  - 罠を踏んだとき: 必ず発見する
- 発見済みの罠には、移動時に「本当に乗りますか？」と確認を出す。
- 罠を踏んだとき、靴の罠回避率に応じて発動しないことがある。
- 敵は罠を発動させない。

### 12.2 宝箱
- 宝箱を調べると開く（1ターン消費）。
- 中身の割合【仮】: 装備70%、消費アイテム20%、お金10%。
- 罠付きの宝箱（20%）は、開けたときにランダムな罠が発動する。

### 12.3 拠点（ベースキャンプ）とメタプログレッション
拠点は、迷宮入口の地下にある「ベースキャンプ」。メニュー形式の画面で、次の施設を持つ。

| 施設 | 内容 |
|---|---|
| 出発 | 新しい挑戦を B1F から始める |
| 道具屋 | 消費アイテムと基本装備（修正値 +0、鑑定済み）を購入する |
| 鑑定屋 | 1品 100G【仮】で鑑定する |
| 解呪屋 | 1品 200G【仮】で解呪し、装備を外す |
| 倉庫 | 最大20枠。挑戦の合間にアイテムを預ける・引き出す |
| 拡張 | インベントリ枠 +5（1000G、2回まで）、倉庫枠 +10（800G、2回まで）【仮】 |
| レシピ手帳 | 手帳を閲覧する |

**引き継ぎのルール**

| 状況 | 失うもの | 残るもの |
|---|---|---|
| 生還（帰還の巻物） | レベル（Lv1に戻る） | 所持品（装備・呪い状態を含む）、所持金（拠点資金に加算） |
| 死亡 | 所持品、装備、レベル、挑戦中の所持金 | 拠点資金、倉庫、拡張、レシピ手帳 |

- 生還時、装備中の呪いは解呪屋で解くまで残る。
- 常に引き継ぐもの: レシピ手帳（発見済みレシピと失敗リスト）、拠点資金、倉庫の中身、拡張状況、クリア回数、最深到達階。

### 12.4 迷宮の行商人【仮】

迷宮の中にも、道具の売買・解呪・解毒を引き受ける「行商人」が現れる。拠点と違い、**支払いは迷宮の中で拾った所持金**で行う。死ねば所持金ごと失うので、使うかどうかがそのまま賭けになる。

- **出現**: ボス階の1つ手前（B19F、B39F、……）には必ず現れる。それ以外の階にも 25%【仮】の確率で現れる（`balance.json` の `spawn` で定義する）。
- **配置**: 焚き火と同じく、周囲に敵・宝箱・罠がない部屋の床に置く。焚き火とは重ならない。敵は行商人のマスに入れない。
- **話しかける**: 行商人のマスか、その隣8マスにいるときにコマンド「話す」を選ぶ。

| サービス | 内容 |
|---|---|
| 買う | 消耗品のみ（薬草・毒消し草・保存食・巻物・矢など）。装備は扱わない。値段は拠点の 1.5 倍【仮】 |
| 解呪 | 300G【仮】。装備したまま解けるので、外せなくなった装備を救える |
| 解毒 | 80G【仮】。かかっている状態異常（`kind` が `ailment` のもの）をまとめて治す。最大HP減少で減った分も戻す |

## 13. セーブ／ロード

- **保存先:** `pyxel.user_data_dir(...)` 配下。
- **形式:** JSON（UTF-8）。各ファイルに `"version"` キーを持たせ、将来の形式変更に備える。

| ファイル | 内容 | 保存タイミング |
|---|---|---|
| `meta.json` | 主人公の名前と見た目、手帳、拠点資金、倉庫、拡張、実績、ランキング | 拠点での操作時、レシピ発見時、死亡時、生還時 |
| `run.json` | 挑戦中の全状態（ランシード、階層、プレイヤー（HP・MP・習得スキルを含む）、所持品、現在の階のマップ・敵・アイテム・FOG、ターン数） | 階を移ったとき、ゲームを終了したとき |

- **中断再開:** タイトル画面の「つづきから」で `run.json` を読み込み、読み込んだ直後に削除する（ロードのやり直しを防ぐ）。
- 死亡・生還・クリアのときも `run.json` を削除する。
- 書き込みは、一時ファイルに書いてからリネームする方式にする（途中で落ちてもファイルが壊れないようにする）。

## 15. 開発フェーズ（AIへのマイルストーン指示）

AIエージェントは次の順で段階的に実装を進めること。

**各フェーズの共通ルール**
- フェーズの最後に、ロジック層の pytest がすべて通ることを確認する。
- 実際に起動して、完了条件（DoD）を満たすことを確認する。
- README の「実装済み機能」を更新する。
- DoD をすべて満たすまで、次のフェーズに進まない。

### フェーズ1: コア実装
- 作業内容:
  - ディレクトリ構成を作成する。
  - Pyxel を初期化し、日本語フォントを読み込む。
  - シードを管理する仕組みを作る。
  - BSP法でマップを生成する。
  - `sprites.json` を介した素材の描画の仕組みを作り、仮のドット絵素材（2.3.1）で主人公・床・壁・通路・階段を描画する。
  - カメラをスクロールさせる。
  - プレイヤーの8方向移動と壁の当たり判定（角抜け禁止を含む）を実装する。
- DoD:
  - 日本語の文字列が画面に表示される。
  - `--seed` に同じ値を渡すと、同じマップが生成される。
  - すべての部屋が到達可能であることをテストで検証している。
  - 壁と角をすり抜けられない。
  - `sprites.json` を書き換えるだけで、表示する素材が変わる。
  - マップとキャラクターの描画に文字（`pyxel.text`）を使っていない。

### フェーズ2: ターン制とUI
- 作業内容:
  - ターンスケジューラ（速度システム）を実装する。
  - 2.3 の画面レイアウトでステータスバーを作る（階層、エリア名、Lv、EXP、所持金、HP・MP・満腹度ゲージ）。
  - コマンドバー（この時点では道具・地図以外は「未実装」と表示してよい）、ログ2行、ログ履歴、全体マップを作る。
  - 満腹度の減少と飢餓ダメージ、HP の自然回復を実装する。
  - FOG（3状態、部屋と通路のルール）を実装する。
  - 下り階段で階層を移動できるようにする。
- DoD:
  - 移動するとターンが進み、満腹度が仕様どおりに減る。
  - 階段で次の階へ進め、新しいマップが生成される。
