# Dungeon & Dine: 飢餓のトレジャーハンター（仮）

モンスターを調理して食いつなぐ、ターン制・8方向グリッドのローグライクRPG。Python + Pyxel 製。

- 開発仕様書: [docs/game_specification.md](docs/game_specification.md)
- コンセプト＆ストーリー: [docs/concept_story.md](docs/concept_story.md)
- 料理カットインの参考画像: `docs/cooking_cutin_concept.jpg`（権利確認が済むまで Git 管理外。必要な人にだけ個別に共有する）

## 動作環境

- Python 3.11 以上
- Pyxel 2.x（`pyxel>=2.0,<3`）
- Windows / macOS / Linux

## セットアップ

[uv](https://docs.astral.sh/uv/) を使う場合:

```bash
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

pip を使う場合:

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

日本語フォント（美咲ゴシック第2 BDF）は `assets/fonts/` に同梱しているので、配置作業は不要。
再配布が許諾されているフォントで、ライセンスは [assets/fonts/README.md](assets/fonts/README.md) と同フォルダの `LICENSE` を参照。

## 起動

```bash
.venv/bin/python main.py
```

| 引数 | 内容 |
|---|---|
| `--seed <int>` | ランシードを固定する（同じダンジョンを再現） |
| `--scale <int>` | 表示倍率（既定 1。2 で 1280×960 に拡大） |
| `--debug` | 開発ビルド扱い（F1 でデバッグ表示） |

## テスト・Lint

```bash
.venv/bin/pytest
.venv/bin/ruff check .
.venv/bin/ruff format .
```

## 仮素材の再生成

```bash
.venv/bin/python tools/make_placeholder_sprites.py
```

`assets/resources.pyxres` のイメージバンクと `data/sprites.json` を上書きする。絵のデータは `tools/sprite_art/` にある。
素材はイメージバンク0から詰めていき、1枚（256×256）に入りきらない分は次のバンクへ送る（送った素材は `sprites.json` に `"bank": 1` を持つ）。使ったバンクは消してから描き込むので、
他の素材を同じバンクに置かないこと。本素材に差し替えたあとは実行しないこと。

## 操作方法

実装済みの操作のみ（全体は仕様書 3.2）。

| 操作 | キーボード | ゲームパッド |
|---|---|---|
| 移動（上下左右） | 矢印キー / WASD | 十字キー |
| 斜め移動 | テンキー 7・9・1・3、または Shift を押しながら2方向同時押し | LB を押しながら十字キー |
| 向きだけ変える | Ctrl を押しながら方向キー | RB を押しながら十字キー |
| 攻撃・決定（階段の上では降りる） | Space / Enter | A |
| キャンセル・閉じる | Esc / X | B |
| コマンドバーへフォーカス | Tab（左右で選択、決定で実行） | X |
| 足踏み（1ターン待機） | . / テンキー 5 / Shift＋Space | LB＋A |
| 道具 / スキル / 装備 / 地図 | I / K / E / M | - |
| 料理（焚き火のそばか携帯コンロ） | C | - |
| レシピ手帳 | R | Y |
| ログ履歴 | L（↑↓でスクロール） | Select |
| デバッグ表示（シード・ターン・座標） | F1（`--debug` 起動時のみ） | - |

コマンドバーのボタンはマウスのクリックでも実行できる。

押しっぱなしにすると 0.15 秒ごとに連続移動する（`data/balance.json` の `input.repeat_interval_sec`）。

## 追加した機能（仕様書の改訂を含む）

- **名前の入力**: 「はじめる」を選ぶと主人公の名前を入力できる（10文字まで。未入力なら「レオ」）。
  五十音表から選ぶ方式で、ひらがな・カタカナ・英数を切り替えられ、「゛」「゜」で濁点・半濁点を付けられる。
  キーボードからの半角英数の直接入力と Backspace も使える。入力した名前は `meta.json` に保存し、次回からの既定値になる。
  Pyxel は日本語の直接入力（IME）を受け取れないため、五十音表を用意した。
- **主人公の見た目**: 名前を入力したあとに、戦士・格闘家・魔法使い・僧侶・商人の5種から選べる。
  選んでいる見た目は、その場で向きを変えながら歩いて全方向の姿を見せる。Esc で名前の入力に戻る。
  **見た目だけの違いで、能力は変わらない**（職業による能力差は仕様書にないため、入れていない）。
  選んだ見た目は `meta.json` に保存して次回の既定値になり、選ぶ前のセーブデータでは戦士になる。
  迷宮の行商人（緑の頭巾）と見間違えないよう、主人公の商人はつば広の帽子と背負い袋にした。
- **持ち物をまとめる／大きな背負い袋**: 拾う道具の数に対して持ち物の枠が少なかったため、2つ追加した（仕様書 11.1）。
  - 草・食べ物・食材・料理・巻物・道具・メモは、同じものを1枠に5個までまとめられる（「薬草×3」のように表示）。
    装備と携帯コンロ（残り回数を個体ごとに持つ）はまとめない。
    まとめた生肉は、いちばん早く腐るものに揃えて一緒に腐る（1枠の中で腐る時間を分けて持てないため）。
  - 「大きな背負い袋」（拠点で400G、行商人も扱う。迷宮でも拾える）を使うと、その挑戦のあいだだけ枠が5増える。1回の挑戦で2つ（+10）まで。
    生還時に拠点の枠より多く持っていれば、そのまま持ち帰れる。ただし枠に空きができるまでは、すでにある枠にまとめられる物しか増やせない。
    拠点では、枠を超えているあいだ「持ち物 24/20」と超過分の案内を警告色で出す。
  - 調理画面では、まとめた材料を持っている数まで続けて選べる。← で1つずつ外し、決定でまとめて外す。
- **ランキング**: ゲームオーバー画面に、これまでの挑戦の順位を表示する（仕様書 6.6）。
  「到達した階層」と「獲得した所持金」の2種類を左右キーで切り替え、それぞれ上位10件を並べる。
  記録は名前・到達階・所持金・ターン数・結果（クリア／生還／力尽きた）で、`meta.json` に最大50件残す。
  今回の記録は黄色、クリアした挑戦は緑で示す。

- **迷宮の深さは無限**: 最下層はない。20階ごと（B20F、B40F、……）にボスが現れ、そのボスを倒すまで下り階段は使えない。
  ボスは5体（奈落の大喰らい／骸骨王／溶岩の暴君／虚無の熾天使／迷宮の造り主）で、使い切ったら先頭へ戻って強化される。
  **B100F の「迷宮の造り主」を倒すとエンディング**。見たあとは「さらに潜る」か「拠点へ帰還する」かを選べる。
- **階層の周回**: B21F から下は B1F〜B20F の20階分をくり返し、エリア名に「（深層2）」のように周回数が付く。
  2周目から下は敵が規則で強くなり（HP +35%、攻撃力 +25%、防御 +20%、経験値 +60%）、名前に「・深種」「・深深種」と付く。
- **敵を25種に増量**: 通常20種＋ボス5体。追加したのは洞窟グモ・沼スライム・屍食鬼・鬼火・石甲虫・骸骨騎士・溶岩イモリ・虚無の蛾と、ボス4体。
  新しい食材4種（蜘蛛の糸・屍肉・燠火の核・蛾の鱗粉）とレシピ4種も追加した。
- **迷宮の行商人**: 迷宮の中で道具の売買・解呪・解毒ができる（仕様書 12.4）。
  ボス階の1つ手前（B19F、B39F、……）には必ず現れ、それ以外の階にも25%の確率で現れる。
  支払いは**迷宮の中で拾った所持金**なので、死ねば当然失う。値段は拠点の1.5倍。
- **迷宮から出る方法は2つだけ**: 「力尽きる」か「帰還の巻物を使う」か。死ねば所持品・装備・所持金をすべて失う。
- **ボスを形で描き分けた**: 以前は5体とも同じ絵の色違いで、縮小表示では同じ敵に見えていた。
  大喰らい（丸い口）、骸骨王（王冠を頂く頭蓋）、溶岩の暴君（角張った岩塊）、迷宮の造り主（菱形）と、
  輪郭だけで区別できる絵に描き直した。
  16×16 の頃は虚無の熾天使の翼が翼として読めなかったが、32×32 に描き直して、光輪・一つ目の頭・衣と
  3対の翼として読めるようになった。
- **画面を 640×480（4:3）、ドット絵を 16×16（ボスは 32×32）にした**: 320×180 に 8×8 では、
  描き分けられる形が少なく、敵の多くが同じ形の色違いになっていた。16×16 では形の種類を増やし
  （ネズミ・トカゲ・犬・クモ・甲虫・騎士・鬼火・行商人）、同じ形を使い回すのは出る階が重ならない敵だけにした。
  文字は美咲フォント（8px）を2倍に拡大して描く。32×32 のボスは文字で1行ずつ書くと数え間違えるため、
  `tools/sprite_art/bosses.py` で円や多角形を重ねて描いている。
  鉱山エリアではレオの髪が床と同じ色で沈んだため、主人公にも敵と同じ黒い縁取りを付けた。
- **敵・宝箱・落ちているものに縁取りを付けた**: 16色しかないため、床の色と同じ色の敵や品物がどうしても出てしまう
  （実際に敵6種とアイテム13品が、出現するエリアの床色と同色だった。とくに灼熱の坑道では保存食・巻物・鎧・靴・槍・鞭・弓が沈んでいた）。
  色を1つずつ変えても新しいエリアや敵を足すたびに再発するため、描画側で1pxの黒い縁を付けて輪郭を分けている。
- **ボスのバランス**: 5体とも、到達レベルの想定・終盤装備・HP満タンで1対1を戦わせた実測勝率が 67〜72% に揃うよう調整した。
  ボスの攻撃力はプレイヤーの防御力の伸び（約1.55倍）に連動させ、手応えは HP と経験値で付けている。
  プレイヤーは最大レベル30（HP272 / 攻撃69 / 防御28）で頭打ちになるため、攻撃力をインフレさせると
  ある階層から先が理論上クリア不能になるため。調整前は B60F 以降の勝率が 12.5% → 0.4% → 0.0% と破綻していた。

## 変更履歴

### v0.3.3

内部の作りを直した版。遊び方・数値・セーブデータは v0.3.2 から変えていない。

- **コードレビューで見つかった3件を直した**
  - 持ち物の「1枠にまとめられる数」を必須の引数にした。渡し忘れると、黙ってまとめられなくなるのではなく、その場でエラーになる。
  - 素材が1枚（256×256）に入りきらないときは、次のイメージバンクへ送るようにした（`sprites.json` の `"bank"`）。
    これまでは素材を1つ足しただけで、素材の生成スクリプトが止まる状態だった。
  - 調理を反映する直前にも、まとめた枠から使う数を検算するようにした（数が合わなければ、何も消費せず取りやめる）。

### v0.3.2

起動時のウィンドウの大きさだけを変えた版。遊び方・数値・セーブデータは v0.3.1 から変えていない。

- **表示倍率の既定値（`--scale`）を 2 から 1 に変えた**
  - 何も付けずに起動すると、ウィンドウは 640×480 になる。
  - これまでと同じ 1280×960 で遊ぶには `--scale 2` を付けて起動する（例: `./run.sh --scale 2`）。

### v0.3.1

主人公の見た目を選べるようにし、持ち物の枠の窮屈さを和らげた版。v0.3.0 のセーブデータはそのまま読み込める。

- **主人公の見た目を5種類から選べるようにした**
  - 戦士・格闘家・魔法使い・僧侶・商人。名前を入力したあとの選択画面で選ぶ（←→で選択、Esc で名前の入力に戻る）。
  - 選んでいる見た目は、その場で向きを変えながら歩いて、4方向の姿を見せる。
  - **見た目だけの違いで、能力は変わらない。**
  - 選んだ見た目は次回の既定値になり、タイトルの「はじめる」から選び直せる。
  - これまでのレオの絵（スカーフと上着の冒険者）は5種類に置き換えた。見た目を選ぶ前のセーブデータは戦士として読み込む。
- **同じ消耗品を1枠にまとめられるようにした**
  - 草・食べ物・食材・料理・巻物・道具・メモは、同じものを1枠に5個まで（「薬草×3」のように表示）。
  - 装備と携帯コンロはまとめない。
  - 使う・投げるは1個ずつ、捨てる・倉庫に預けるは1枠まるごと。料理では、まとめた枠から持っている数まで材料に選べる。
  - まとめた生肉は、いちばん早く腐るものに揃えて一緒に腐る。
  - v0.3.0 までのセーブデータで別々の枠に入っている持ち物は、そのまま。これから拾ったり買ったりした物からまとまる。
- **新しいアイテム「大きな背負い袋」を追加した**
  - 使うと、その挑戦のあいだだけ持ち物の枠が5増える。1回の挑戦で2つ（+10）まで。
  - 拠点の道具屋で400G、迷宮の行商人で600G。迷宮にも落ちている。
  - 生還したときに拠点の枠より多く持っていれば、そのまま持ち帰れる。
  - 出発するときに拠点の枠を超えた持ち物が消える作りだったため、背負い袋で持ち帰った持ち物が失われないよう直した
    （袋を入れる前は枠を超えて持つ手段がなかったので、v0.3.0 までに実際に起きることはなかった）。

### v0.3.0

画面と素材を一回り大きくした版。遊び方・数値・セーブデータの形式は v0.2.2 から変えていない（そのまま続きから遊べる）。

- **画面を 320×180（16:9）から 640×480（4:3）に広げた**
  - 1マスを 8px から 16px にし、マップの表示範囲は 40×15 マスから 40×22 マスに広がった（縦に広く見渡せる）。
  - 文字は美咲フォント（8px）を2倍に拡大して描く。行の高さは 20px。
  - 表示倍率の既定値（`--scale`）を 4 から 2 に変えた。ウィンドウの大きさは 1280×960 になる。
    画面に収まらない場合は `--scale 1` で起動する。
- **すべての画面のレイアウトを作り直した**
  - ステータスバー・コマンドバー・ログ・道具・装備・スキル・行商人・レシピ手帳・地図・ログ履歴・確認ダイアログ、
    タイトル・拠点・名前入力・ゲームオーバー（ランキング）・エンディング。
  - 縦に余裕ができたので、以前から重なっていた箇所を直した（スキル7個で説明文と重なる、拠点の一覧とメッセージが重なる、
    地図が横長に歪む）。
  - 料理カットインは、背景の絵（320×140）を2倍に拡大して中央に置く。上下の余白は暗い色で埋める。
- **ドット絵を 8×8 から 16×16（ボスは 16×16 から 32×32）に描き直した**
  - 地形・レオ・敵20種と行商人・宝箱・アイテム・罠のすべて。
  - 敵の形を8種類増やした（ネズミ・トカゲ・犬・クモ・甲虫・騎士・鬼火・行商人）。
    同じ形の色違いは、出る階が重ならない敵だけに減らした。
  - ボス5体は、2コマ目の動きも描き分けた（大喰らいは口を開き、骸骨王は顎が落ち、溶岩の暴君は割れ目が燃え上がり、
    熾天使は翼を下ろし、迷宮の造り主は迷路が回る）。
  - 主人公にも黒い縁取りを付けた（灼熱の坑道で、髪が床と同じ色で見えなくなっていたため）。
- **開発者向け**
  - 絵のデータを `tools/sprite_art/` に分けた。`tools/make_placeholder_sprites.py` は並べて書き出すだけになった。
  - `game/config.py` に、画面上のマスの大きさ（`TILE_SIZE`）と素材の大きさ（`SPRITE_SIZE`）を別々に持たせた。

## 手元でのテストプレイ

仮想環境のパスを打たずに起動できるスクリプトを用意している。起動引数はそのまま `main.py` に渡る。

```bash
./run.sh                 # macOS / Linux
./run.sh --seed 123 --scale 2
```

- macOS では `run.command` を Finder でダブルクリックしても起動できる。
- Windows では `run.bat` を実行する（`run.bat --seed 123` のように引数も渡せる）。

## 配布用ビルド

Mac / Windows / Linux の実行ファイルを作れる。PyInstaller は実行した OS 向けの実行ファイルしか作れないため、
3 OS 分は GitHub Actions（`.github/workflows/build.yml`）で各 OS のランナーがビルドする。

```bash
# 手元の OS 向けにビルドする（dist/ に出力）
uv pip install --python .venv/bin/python pyinstaller
.venv/bin/python tools/build.py
```

- GitHub 上では、`v` で始まるタグを push するか、Actions の画面から手動実行するとビルドが走る。
  成果物（`DungeonAndDine-macos` / `-windows` / `-linux`）は Actions の artifacts からダウンロードできる。
- ビルドした実行ファイルには `assets/` と `data/` を同梱する。`game/config.py` は、実行ファイルとして
  起動した場合に展開先のフォルダを見るようにしている。

## 実装上の判断（仕様書 16章）

- 仕様書などの資料は `docs/` にまとめた。
- 仮素材の生成スクリプトは `tools/` に置く。
- 仕様書 2.8 の構成に加え、`world/direction.py`（8方向）、`ui/camera.py`（カメラ位置の計算）、`ui/input.py`（入力の解釈）を追加した。
- カメラはプレイヤーを中心にするが、マップの端ではマップ外が映らないように止める。
- 部屋や通路に接していない岩盤は描画せず黒のままにする（部屋と通路の輪郭だけ壁を描く）。
- BSP の分割区画・部屋サイズの上下限は `balance.json` の `mapgen` で定義する。兄弟区画の部屋どうしを、中心が最も近い組み合わせでL字の通路でつなぐ。
- ラン中の状態とターン進行は `systems/game_state.py`（pyxel 非依存）にまとめ、シーンは入力と描画だけを担当する。ログの保持は `systems/message_log.py`。
- 階段を降りる操作と、壁に向かって向きだけ変わった移動はターンを消費しない。
- 満腹度の減少は % 単位の整数で蓄積し、呪い・装備による倍率（0.8倍・2倍）を誤差なく扱えるようにした。
- 初期ステータスの防御力は、`balance.json` では `defense` キーで定義する（`def` は Python の予約語のため）。
- B20F はフェーズ7で固定のボス階にするまで、B20F の階段からはそれ以上降りられないようにしている。
- 未実装の効果を持つアイテム・スキル（帰還の巻物など）は、選ぶと「未実装」とログに出す（ターンは進まない）。「料理」は焚き火のそばにいるか、携帯コンロを使えるときだけ選べる。
- 敵・アイテム・罠・状態異常・スキルの定義は `systems/catalog.py` でまとめて読み込み、ID の相互参照（出現テーブルの敵、能力の状態異常など）を起動時に検証する。
- 敵の命中率・回避率は仕様書にないため、`enemies.json` に命中85・回避0〜15として定義した。
- 経験値はレベルアップのたびに必要量を差し引く（ステータスバーの EXP は「現在値/次のレベルまで」）。
- 敵がプレイヤーに気づけるのは、プレイヤーの視界（盲目の影響を受けない）に敵が入っているとき。chase 型は気づくまでその場で待ち、wander 型は徘徊する。
- 投げる・捨てるは1ターン消費する。投げたアイテムは敵に当たると失われ、当たらなければ着地点（空いていなければ近く）に落ちる。
- ムチでアイテムを引き寄せたときは、そのまま拾う。
- 混乱中は方向がランダムになるため、発見済みの罠の確認ダイアログは出さない。
- 「捨て身の一撃」の反動ダメージで HP が0になった場合も力尽きる。
- 印と呪いの種類・効果量、修正値の出やすさは `balance.json` の `equipment` で定義する。
- 呪いの有無と種類は装備の生成時に決める。呪われた装備の修正値は最初から -3〜-1 にしておき、装備した時点で呪いが発動する（未鑑定の間はどちらも見えない）。
- 宝箱は通り抜けられない（開けたあとも同じ）。移動でぶつかるか、正面を向いて攻撃キーで開く。中身は直接手に入り、持ちきれなければ足元に置く。罠付きの宝箱は、中身を受け取ったあとに罠が発動する。
- 投げる・捨てるときに装備中のアイテムは自動で外す。呪われていれば外せないので投げることも捨てることもできない。
- 靴の「罠回避率」（仕様書 12.1）は、草履 0%・革の靴 10%・鉄の靴 20% とした。
- 盾のブロックは敵の近接攻撃にだけ効く（炎のブレスは防げない）。
- 聖水は呪われていない装備にも使え、修正値が +1 される。「目利き」の対象は、未鑑定で呪いの有無もわからない装備。
- 「視界-1」の呪いは、通路で見える周囲の範囲を1つ狭める（0 より狭くはならない）。
- 鎧の最大HPボーナスは装備したときに最大HPへ加え、外すと差し引く（HPは新しい最大HPを超えないように切り詰める）。
- 「炎」の印（倒した敵の食材が焼ける）と「料理の失敗率+30%」の呪いは、効果の値だけ持っておき、フェーズ5で料理に反映する。
- 料理の結果は材料を選び終えた時点で決め、カットインから探索画面へ戻るときに反映する。段階1〜5の間はターンが進まず、戻ったところでちょうど1ターンだけ経過する。
- 食材が腐るまでの時間は、手に入れた（敵が落とした）ターンから数える。床に落ちたままの生肉も腐る。
- 「焼き〇〇」は肉類の食材にだけ用意した。焼いた食材・料理・謎の物体・腐った肉はアイテムとして手に入り、あとから食べられる。
- 既知のレシピでも失敗することがあるが、失敗リストに記録するのは「一致するレシピがない組み合わせ」だけにした（正しい組み合わせに ✕ が付かないようにするため）。
- 焚き火はタイルではなく階の付属物（`Floor.campfires`）として持つ。安全地帯は焚き火から1マス以内（周囲8マス）。
- カットインの演出時間、調理演出の短縮、ワイプの省略は `balance.json` の `cooking.cutin` で設定する（設定画面はフェーズ6以降）。
- カットインの背景は `assets/cutins/cooking_<エリアID>.png` があれば使い、なければ単色と図形で仮の背景を描く。炎・湯気などの部品も仮に図形で描いている（本素材はフェーズ7）。
- レシピ手帳は `meta.json` に保存し、挑戦をまたいで残る。
- 道具屋の品揃えは、`price` を設定したアイテムとした（刀・大盾などのレア装備は非売品）。矢だけは `base_camp.bundles` で10本単位で売る。
- 拠点の「持ち物」と「倉庫」は別の枠。出発すると持ち物をすべて持ち込み、拠点側には残らない。
- 死亡・生還の引き継ぎは `systems/meta.py` にまとめ、シーンからは `finish_run` だけを呼ぶ。生還時の装備は呪いも含めてそのまま持ち帰る。
- 保存先は `pyxel.user_data_dir` で解決するが、これは `pyxel.init` のあとでないと呼べないため、`App` で求めてロジック層（`systems/save.py`）にはパスだけを渡す。
- `run.json` には乱数の状態も保存し、再開しても出目が変わらないようにした。マップはランシードから再現できるが、戦闘やドロップの乱数は途中経過を持つため。
- セーブデータが壊れていたり、形式のバージョンが違ったりしたときは、エラーにせず新しいデータとして扱う。
- ゲームオーバー画面からは拠点に戻る（タイトルには戻らない）。
- フェーズ7で見直した【仮】値（`tools/simulate.py` の自動プレイで確認しながら調整した）:
  - レベルアップの伸び: 最大HP +5→**+8**、最大MP +2→**+3**、力 +1→**+2**
  - 敵の経験値: おおむね2倍（巨大ネズミ 3→**5**、骸骨兵 10→**20**、迷宮の番犬 45→**90** など）
  - 食料まわり: 満腹度の減少間隔 10→**14**ターン、食材のドロップ率 30→**35%**、焚き火の出現 30→**40%**、保存食の出現重み 12→**18**
  - ボス「奈落の大喰らい」: HP 300→**240**、ATK 28→**26**
- バランスの確認結果（自動プレイ。簡単な方針で動くため、人が遊ぶ場合の下限の目安）:
  - ボス戦のみ: Lv10 で20%、Lv12 で50%、Lv15 で80% のクリア率。到達時のレベル次第で勝負になる強さにした。
  - B16F から始めた終盤の通し: Lv15 で55%、Lv20 で75% がクリアに到達する。
  - B1F からの通し: 平均 B10F まで到達し、B20F へ着くのは 4〜8%（そのとき平均 Lv13 前後）。
    自動プレイの立ち回りを改善（強い装備への持ち替え、ボス階の焚き火で全快してから挑む、満腹度を保つ）した結果、
    **B1F から通しでクリアする挑戦が出るようになった**。ただし到達自体が少ないため、通しのクリア率は数％にとどまる。
  - 自動プレイは簡単な方針で動くため、人が遊ぶ場合の下限の目安として見ること
    （保存食を残す、料理でしのぐ、拠点で装備を整えるといった判断はしない）。
- ボスの経験値は仕様書にないため 500 とした（倒すとその場でエンディングに入るため、実質は記録用）。
- 「攻撃を受けた側の点滅」は、スプライトの上に白いディザ矩形を重ねて表現している。
- 音は `data/sounds.json` に定義し、起動時に `pyxel.sounds` / `pyxel.musics` へ読み込む。BGM はエリアIDで切り替える。
- 料理カットインの背景 PNG は、パレット番号を保つために既定のパレットのまま書き出し、表示するときに料理用パレットへ入れ替える。
- **深層の飢餓はゲーム側の問題ではない**（調査済み。数値は変更していない）。
  - 自動プレイの深層では飢死が多い（B41F 開始で 46〜58%）が、食料の供給は消費の6倍以上ある。
    1階あたりの消費は満腹度 7.1（浅層）〜13.3（深層）で、床に落ちる保存食だけで期待値 83.3。
  - 原因は `tools/simulate.py` の立ち回り。飢死の瞬間の持ち物を調べると、10件すべてで
    薬草・魔力草・毒消し草だけを10個前後抱えていた。**これらは満腹度を回復しない**（保存食のみ +50）。
    床に保存食が残っている階で飢死していた例もある。
  - 試して**悪化した**対策（同一シードでの比較。再挑戦するなら避けること）:
    - 敵の追跡をやめる → 飢餓 58%→50%、歩数もほぼ変わらず。追跡は主因ではない。
    - 空腹時に床の食料を距離無制限で取りに行く → 飢餓 58%→**79%**、1階 278→719ターン。
      食料を求めて歩き回るぶん、かえって飢える。
    - 上を8マス以内に制限 → 飢餓 71%、1階 557ターン。依然として修正前より悪い。
  - 自動プレイは「人が遊ぶ場合の下限の目安」であり、この飢死率をもってゲームの数値を
    変更する根拠にはしない。直すなら `tools/simulate.py` の立ち回りのほうで、
    かつ同一シードでの比較と十分な試行数（24回では雑音が大きい）で確かめること。
- **自動プレイの行商人対応は、実装しても効果が出なかった**（調査済み。取り込んでいない）。
  - 隣接したら解呪→解毒→保存食の購入を行う立ち回りを書き、動作は確認した
    （購入・解毒・解呪・所持金不足の判定・寄り道の距離制限、いずれも意図どおり動く）。
  - それでも成績は基準値と**完全に一致**した（深層 B41F Lv20・24回で
    進んだ階数 13.9／飢餓 58%／到達 B53.9F。通し B1F も 8.2／38%／B8.2F で同一）。
  - 原因は取引がほとんど発動しないこと。**深層8試行で1回、浅層6試行で0回**。
    飢死した試行の所持金は 0〜319G で、保存食（90G）を買う判断の閾値にも届かない。
    行商人に会える階では金がなく、金が貯まった頃には行商人がいない。
  - **ターンを消費しない行動を step() に足すときの落とし穴**（行商人に限らず再発する）:
    取引はターンを消費しないため、「何も起きていないのに True を返す」と step() が
    毎回そこで抜けて同じ判断を繰り返し、ターンが進まないまま停止する。
    持ち物が満杯で買えないときに実際に無限ループになり、測定が無言で止まった。
    所持金が実際に減ったかなど、**状態が変わったときだけ True を返す**こと。
